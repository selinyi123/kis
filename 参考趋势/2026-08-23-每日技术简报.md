## 3. 技术趋势与架构参考

```text
Intent / Goal
    ↓
Organization / Session
    ↓
Policy + Budget + Trust
    ↓
Runtime / Tool / Secret
    ↓
Artifact / Evidence
    ↓
Verification
```

三个判断：

1. Agent 管理面正在组织化，但管理面不应拥有第二套 side-effect authority。
2. Credential 权限正在从“谁能读”升级为“允许发送到哪里、多久、什么 task scope”。
3. Context engineering 更适合 progressive disclosure，而不是无限 Top-K；需要记录 exact revision、trust state 与 selection reason。

## 4. 对五个项目的机会、风险和行动建议

### DPMS
维持现有幂等动作、状态回读、Evidence 与 real-run gate。吸收 Paperclip 的 Goal/Budget 管理对象，但只做 Control Surface。优先设计 `CredentialGrant v0.1`，将平台 credential 与 adapter、destination host、scope、TTL 绑定。

### Prompt Performance Engine
当前 0.4.0 已具备 deterministic audit、fail-closed preflight、budgeted execution host、offline replay、receipt verifier。建议新增 Context Topology Ablation：比较 giant instructions、short map + structured docs、retrieved relevant docs，并测 correctness/cost/context/tool calls/failure class；另做 unauthorized-destination policy benchmark。

### KIS
当前 canonical / derived 分离和人工确认队列边界正确。最值得新增：

```text
ContextBundle
├ selected_cards[]
├ exact_revisions[]
├ trust_states[]
├ selection_reason
├ token_budget
├ generated_at
└ consumer_session
```

目标不是“检索更多”，而是能回答：某次 Agent run 实际看到了哪些知识、哪个版本、为什么选择、可信状态如何。

此外建议把 docs/design/architecture/decision 作为显式 Artifact 类型，支持 freshness、supersession 和 provenance，而不是全部降维成普通文本片段。

### ClipVault
不扩功能。未来 OTP/secret transport 预留 destination_device、destination_app、TTL、one_shot、persistence=forbidden，发送目标不匹配时 fail-closed。

### Binggo
适合做 Goal + Budget + inspect/explain/preview 的小型 Agent Control Surface，所有写动作继续走现有 deterministic executor、风控与状态回读。

```text

ContextSelection
CostProfile
PolicyDecision
TrustContext

```
