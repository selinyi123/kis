# 每日技术简报｜2026-08-23

## 今日结论

今天最值得追踪的不是新模型，而是 Agent Runtime 的两个基础能力正在快速成熟：

1. **Runtime Event Log / durable authority**：执行日志不再只是观测数据，而开始成为 session、恢复、UI、上下文投影和审计的权威来源。
2. **Cost / cache / budget engineering**：缓存命中、cache write/read、token、tool-call 上限和 per-run spending 正逐渐成为 Agent 配置的一部分，而不是账单后的统计。

对 DPMS / PPE / KIS / ClipVault / Binggo 的共同启示是：下一阶段最值得共享的 primitive 不应继续扩成新的 Agent 协议，而应围绕 `ExecutionRecord / ContextRef / CostProfile / PolicyDecision / Evidence` 建模。

## 2. 今天最值得看的开源项目

### Apache Maka

GitHub： https://github.com/apache/maka

Maka 的核心表述是 **Log is the Runtime**：模型消息、Tool Call、Tool Result、permission decision、termination fact 都进入 Runtime Event Log；Session、UI、Context、Recovery 是日志投影。

它还明确区分“Context”和“History”：Tool Result pruning 与 compaction 可以改变下一次 inference 看见的内容，但不销毁执行证据。

```text
Runtime Host
   ↓
AgentRun
   ↓
Runtime Event Log
   ↓
Session / UI / Context / Recovery projections
```

### Vercel Labs / fx

GitHub： https://github.com/vercel-labs/fx

`fx` 是 Zig 编写的极小型 coding-agent harness，强调 embeddability、Skills、MCP、subagents、权限和 WASM 嵌入。近期 PR 集中在 permission consistency、destructive action review、subagent retirement、auth ownership、goal tracking、MCP timeout，说明真正的 Runtime 难点已经转向生命周期与边界治理。

### Windows AppContainer sandbox

Maka 0.1.11 加入 brokered Windows AppContainer sandbox，并强化 IPC ownership / ACL。对 Windows-first 的本地 Agent 产品，这是比继续套 Linux container 更值得研究的方向。

## 3. 技术趋势与架构参考

### Context、History、Evidence 应拆开

```text
Evidence → 永久执行事实，不因 token budget 删除
History  → 人类可浏览的交互记录
Context  → 当前 inference 实际注入的有限工作集
```

### Event Log 可以成为执行事实 authority，但不能替代外部副作用 reconciliation

Agent Runtime 可以用 append-only facts 驱动 UI、恢复、审计与 context projection；但对点赞、支付、文件写入等不可逆 side effect，仍必须保留 indeterminate / reconciliation 状态，禁止依据“没有 success event”直接重试。

### Cost Profile 应进入 Eval

一个 Agent Run 至少应绑定：

```text
ModelConfig
PromptRevision
ContextPolicy
CachePolicy
ToolPolicy
ExecutionBudget
```

并测量 quality、success、cache read/write、uncached input、output、tool calls、wall time、cost。

## 4. 对五个项目的建议

### DPMS

增加只读 `ExecutionRecord` projection，复用现有 DB/event/audit/evidence，不替换 real-run authority。

### Prompt Performance Engine

增加 `CostProfile + CachePolicy`，做 CachePolicy A/B、Budget Sweep、Context Layout Ablation，输出 quality × reliability × cost Pareto frontier。

### KIS

KIS 当前 canonical / derived 分离与人工确认边界应保持。今天最值得新增的是：

```text
ContextSelection
├ task/session id
├ selected card ids
├ exact revision/content hashes
├ selection reason
├ token budget
├ trust state
└ generated_at
```

这会让 KIS 从“能检索知识”升级为“能证明一次 inference 实际使用了哪些知识版本”。

机会：以后 PPE 可以直接对 ContextSelection 做 ablation；DPMS 可以把它挂到 ExecutionRecord；错误分析时可以区分 missing knowledge / retrieval failure / reasoning failure。

风险：不要把 Runtime Event Log 和 KIS Knowledge Store 合并。Runtime log 是执行事实，KnowledgeCard 是知识资产，二者 authority、生命周期、保留策略完全不同。

### ClipVault

不扩功能边界。继续 local-first，并预留 origin/source_app/content_hash/sensitivity/persistence_policy/session_ref；OTP、credential、secret 继续隔离。

### Binggo

增加只读 Run Trace / Action Preview；让 Agent 做 inspect → explain → preview，确定性 executor 保持真实动作 authority。

## 5. 今天建议执行

1. DPMS：`ExecutionRecord v0.1`。
2. PPE：`CostProfile + CachePolicy` PoC。
3. KIS：`ContextSelection` artifact，并保证其只引用 canonical/approved 或显式标注 trust state 的内容。
4. Binggo：只读 Run Trace；ClipVault 暂不扩功能。

## 今日最终判断

今天值得稳定下来的三个对象是：

```text
ExecutionRecord  → 这次执行发生了什么？
ContextSelection → 模型当时实际看到了什么？
CostProfile      → 为这次结果付出了多少资源？
```

对 KIS 而言，最有价值的不是再增加一种 Memory，而是把“知识选择本身”变成可版本化、可审计、可评测的 artifact。
